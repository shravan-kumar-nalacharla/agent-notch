# 0.13.0 — microphone privacy and browser tasks

## What changed

Microphone availability is now a persisted application policy, independent of system volume. The island, Voice & typing settings, tray and configurable global shortcut can mute it. The default mute shortcut is Ctrl+Alt+M; Windows conflicts are shown in Settings and users can choose another combination. Muting while hidden keeps the island hidden. Gaming / Meeting Mode provides a separate, reversible pause without changing the user's mute choice.

New installations use Manual activation only. Push-to-Talk uses a held shortcut (default Ctrl+Alt+V), releases capture on key-up, and processes a command after release. Always listening is an explicit opt-in. The existing dictation shortcut remains available in manual mode when enabled with a speech key and cloud-audio consent. Mute blocks dictation, manual activation, meetings, wake recognition, Live audio and local microphone tests. Timers, Spotify and reminders retain their own settings.

Microphone mode, call-app selection and shortcuts now participate in the main **Save changes** action. The microphone Apply button uses that same save path. Mute and Gaming / Meeting switches act immediately; saving unrelated settings preserves their current state. Invalid shortcut combinations fail validation without committing new settings. Keys remain encrypted on disk and retain the separate provider inputs from 0.12.0. Groq remains the default; Gemini Live is optional.

## Root causes and implementation

* `src/commands.cjs` previously allowed its search shortcut to consume a complete compound request. `src/intent-router.cjs` now distinguishes search-only requests, sequenced actions, quoted/explanatory commands and corrections. The 18 supplied cases are checked in as `tests/fixtures/routing-regressions.json`. “Google AI Studio” is treated as a product name rather than a search verb.
* `src/task-coordinator.cjs` admits typed, conventional voice and Gemini Live tasks through one coordinator. It retains utterance deduplication, cancellation, pause/continue, encrypted recovery checkpoints and bounded redacted diagnostics. A recovered task requires explicit continuation; actions are not replayed at startup.
* `src/browser-controller.cjs` uses Playwright and a dedicated persistent profile rather than sending every instruction to a search URL. Fresh DOM references ground actions; changed controls are rejected. The known AI Studio flow selects the official organic result, hands sign-in back to the user, and verifies origin, route and heading. Generic browser tasks use bounded planning and a destination verifier. Completion text alone is insufficient.
* `src/microphone-privacy.cjs` gates voice entry points, cancels pending uploads and voice tasks, and sends native mute immediately even if an earlier configuration is waiting. Epochs reject obsolete configurations. Native failure blocks capture and terminates only the owned helper.
* `native/IslandNative/Privacy.cs`, `Program.cs` and `WakeWord.cs` stop/dispose recording, wake recognition, meeting capture, held-key hooks and native speech on mute. Renderer listeners release local media tracks and stop queued/cloud/Live playback. Audio-device enumeration now runs off the native control thread: Windows testing reproduced enumeration blocking a mute acknowledgement before this change.
* Packaged desktop automation exposed a missing runtime dependency: the new publish folder contained only the helper executable and license, while UI Automation needs the five WPF native DLLs retained in earlier releases. `scripts/build-native.cjs` now copies them from the matching build output, and `prepare-package.cjs` refuses to package an incomplete native runtime. Native dependencies can remain separate from a .NET single-file executable. [Microsoft deployment documentation](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview).
* `src/microphone-ui.js`, `renderer.js` and `main.cjs` connect the privacy controls to the shared save path, native gate, shortcut registration and tray. Privacy is checked again after asynchronous recording preparation so a late activation cannot restart a muted microphone.

## Call detection

Optional auto-mute inspects active Windows microphone sessions for selected process names, initially Discord. Merely opening Discord does not trigger it. This is a conservative microphone-use signal, not proof of a call: muted calls or some audio stacks may not expose an active session. No audio or Discord account data is read. If the probe is unavailable, enabling auto-mute pauses capture and displays the reason. Use manual Gaming / Meeting Mode when reliable call information is unavailable. Ending automatic suppression does not clear an explicit user mute.

## Supported browser modes and privacy boundaries

| Mode | Behavior |
| --- | --- |
| Managed Chromium | Runtime bundled with the installer; dedicated Agent Notch profile. |
| Brave | Uses the installed executable with a separate Agent Notch profile; local headed fixture tested. |
| Chrome / Edge | Executable discovery and dedicated profiles implemented; real-browser checks pending. |
| Existing everyday browser profile | No implicit attachment or reuse. Sign in separately in the managed browser. |
| Native Windows applications | Existing UI Automation path remains available. |

Browser operations accept public HTTPS destinations by default, reject credentials/private destinations and unsupported schemes, and do not execute model-generated shell or JavaScript. Page contents are untrusted data. Sending/submitting and other sensitive actions wait for visible review; secret creation/reveal is blocked by the browser executor. Sign-in, MFA and CAPTCHA remain manual. Diagnostic exports omit raw goals, credentials and secret fields. Browser profile cleanup is explicit in Diagnostics; uninstall keeps personal data unless the user explicitly selects erasure.

## Validation and remaining work

Evidence is stored under `artifacts/0.13.0`; the release QA archive contains the machine-readable report, logs and safe screenshots. Tests use disposable profiles and fixture credentials, never the user's saved API keys.

Final automated results (2026-11-04): 204 unit/integration tests; 71 packaged app/UI assertions (privacy 13, save 15, settings 23, notch reminders 11, Windows tasks 9); 22 packaged headed-browser fixture assertions (Chromium 11, Brave 11); native privacy 8; held-key lifecycle 5 across three consecutive runs; app restart persistence 4. These suites overlap in coverage and should not be interpreted as independent user scenarios. Integrity checks match all 109 packaged source files, seven native resources and the bundled Chromium executable to their tested inputs. The existing Windows installation was not upgraded or uninstalled during these checks.

The actual NSIS payload was extracted and compared byte-for-byte: its app archive, seven native resources and Chromium executable match the tested package. A cached archive initially retained an older helper, so the final installer was rebuilt in a fresh output directory on F:. C: ran short of space during compression. The verified installer is also available at `F:/AgentNotch-builds/0.13.0/Agent Notch Setup 0.13.0.exe`; select F: as the installation destination while C: remains low. Extracting the payload does not claim that the installer or uninstaller was run.

Verified on Windows 11 (build 26300): unit/integration routing and privacy tests; real native microphone capture/disposal; immediate mute during device enumeration; held-key capture, release and no shortcut leakage into a focused fixture; hidden-island global shortcut activation/conflicts; shared Settings save and invalid-save rollback; actual app restart with a persisted mute; local headed browser authentication handoff, API Keys verifier, sponsored-result skipping, stale-target handling, SPA/new tabs, review rejection, cancellation, recovery and generic browser navigation.

Repeated held-key checks exposed a real early-release bug: polling the swallowed key's asynchronous Windows state could stop capture on a timer tick. The hook now tracks the key-up event directly, while checking modifier release separately. The strengthened test requires capture to remain active across several ticks before release. These are injected Windows events through the actual low-level hook, not a physical keyboard or Discord call test. The native capture test discards audio without saving or uploading it.

Live Google testing reached the sign-in handoff. Authenticated AI Studio navigation, actual spoken multilingual end-to-end commands, live Groq/Gemini/DeepSeek capability/latency, physical shortcut use, a real Discord call, Windows 10, startup after Windows login and a full uninstall were not verified. The known-site fixture does not prove those scenarios. Chrome/Edge and existing-profile attachment are not claimed as tested. No demo of completed authenticated voice navigation was produced. The installer is unsigned.

## Reproduce checks

```powershell
npm test
npm run build:native
node scripts/check-native-privacy.cjs
node scripts/check-ptt.cjs
node scripts/check-privacy-restart.cjs
npm start -- --smoke-test --privacy-check
node scripts/check-browser-agent.cjs
dotnet publish tests/windows-fixture/WindowsFixture.csproj -c Release -r win-x64 --self-contained false -o artifacts/0.13.0/windows-fixture
npm run dist -- --config.directories.output=release/0.13.0
node scripts/check-packaged.cjs
```

For first use, open **Settings → Voice & typing → Microphone & privacy**. Choose a listening mode and shortcuts, then Save changes. Enable cloud audio and save the chosen speech provider key when using transcription. If Ctrl+Alt+M is reported unavailable, choose another shortcut; Ctrl+Alt+F9 was verified on this machine. For a private call, mute the microphone or enable Gaming / Meeting Mode before speaking.
