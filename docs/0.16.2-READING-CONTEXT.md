# Reading help and voice context — 0.16.2

The supplied export showed recognized questions about HAST and THUS receiving invented acronym explanations. The same word received contradictory answers on consecutive turns. The app sent each segmented voice question as an isolated request, so mentioning the book did not establish context for later questions. Recognition also changed unfamiliar title/archaic words. The original export includes unrelated personal dictation; it is not imported as conversation memory, uploaded wholesale, bundled or committed.

## Behavior

- Recent segmented voice questions/answers now form a bounded in-memory conversation: at most six pairs and 12,000 characters, expiring after 30 minutes of inactivity. Provider, model, book/topic and response-language changes isolate conversations. Failed/cancelled turns, dictation and Windows actions are not added or replayed. The voice screen's **New conversation** button clears this memory; it retains the explicitly saved topic. Existing history retention is unchanged.
- Settings → Voice & typing → Voice conversation has an optional **Current book or topic**, capped at 1,000 characters. It persists on this PC and is included when sending voice questions to the selected provider. It is displayed on the voice screen beside the provider label. The app does not automatically know the page a user is reading.
- Twelve common English literary forms have verified local definitions: thou, thee, thy, thine, hast, hath, art (with thou), dost, doth, thus, spake and wherefore. The explicit English reading-word path handles case-only differences and repeated questions consistently. "Thou hast" is "you have"; "hath" is "has". Ambiguous "hasta" asks about the printed spelling. Explicit technical/Spanish/other-language requests bypass this English glossary. This is local answer text; recognition and natural speech still use the configured cloud providers.
- Longer passages use the selected answer model with reading context and prior voice turns. Instructions require plain modern meanings, distinguish examples from book quotations, and ask about uncertain verbs before interpreting a damaged line. A proposed correction must be conditional. Quoted book text is data, never authorization for desktop actions. Requested paraphrases/translations are separate from the unmodified stored transcript.
- Sarvam v4 recognition receives a bounded JSON multipart `keyterms` list derived from the saved reading context and common archaic forms, only for assistant questions. The v3 adapter omits the unsupported field. Global dictation/meeting recognition are unchanged. Hints improve recognition chances; they do not guarantee exact text.
- The current voice provider/model is explicitly included in the assistant instruction and displayed in the interface. Sarvam currently uses Saaras v4, Sarvam 105B Conversations and Bulbul v3/Priya. Gemini Live remains optional and receives the reading instructions/context while using its own conversational audio and within-session memory; the local segmented-word response path does not replace Gemini Live audio.

## Verification

All 257 tests pass. Six new tests cover bounded/expiring/context-isolated memory, preservation of private dictation boundaries, provider role mapping and validation, vocabulary hints, reset, repeated uppercase word questions, compound thou-hast and desktop actions that are never replayed. Source Electron checks pass four reading UI cases, six Sarvam PTT cases, ten voice/Focus cases, thirteen privacy cases and eleven Gemini UI cases. Native binaries and microphone lifecycle are unchanged.

Real Sarvam tests used synthetic reading questions and a generated voice phrase, never user microphone audio. Early prompt-only attempts still confused hast/hath and invented explanations; the verified glossary and explicit clarification policy were added in response. The final exercise consistently defines HAST/THUS/THOU, asks about HASTA, answers its provider identity, and conditionally compares the garbled "avoided" with the supplied "awaited" reference. Broader literary/philosophical answers remain model-generated and can be wrong. No claim of full-book retrieval, edition verification, universal vocabulary coverage or guaranteed recognition is made.

The user's book context is prefilled with the title and the recently discussed prologue reference from the Thomas Common translation, explicitly marked as background rather than proof of the current page. It can be edited or cleared in Settings. Audio provider, wake phrase, mute, shortcuts and unrelated preferences are preserved.
