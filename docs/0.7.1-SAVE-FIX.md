# Agent Notch 0.7.1 save and Windows fixes

The global voice checkbox no longer switches itself off when cloud-audio consent or a speech key is missing. Save now retains the requested preference and explains what is needed to activate it. The audio-consent checkbox, hotkey selection, microphone and live readiness message are together at the top of Settings → Voice. Microphone actions route to that section when permission is missing. Audio upload still requires an explicit user choice.

The native voice configuration is serialized and awaited before readiness is reported. This also fixes a startup race where an in-progress native initialization could skip a later Enable request. The checkbox reflects the saved preference; the readiness text reflects whether the Windows hook actually started.

API keys save independently of voice readiness. A saved-key indicator requires successful decryption into the main-process cache. Locked credentials get a recovery message instead of looking configured. Unsaved API-key drafts survive provider switching; unsaved settings survive unrelated background updates. Settings failures remain visible until corrected and are repeated in the persistent save bar. A success message is never used to imply a provider connection was tested.

Settings now has one content scroll container, a visible scrollbar, a separate navigation column and a save bar outside the scroll region. The bar cannot cover the final controls. The quote library no longer creates another nested scroll container, and unrelated library events do not rebuild the quote list or move the scroll position.

Start with Windows is a persisted preference, defaults on, and is applied when the packaged app starts. Registration and readback use the same quoted executable path and arguments, including development-mode arguments. Electron 44's readback parses paths as command lines and checks the current AppUserModelID; the startup name therefore matches `app.agentnotch.desktop`. The entry is explicitly enabled and checked after registration; the tray and settings share the saved value. See [Electron's matching-argument requirement](https://www.electronjs.org/docs/latest/api/app#appgetloginitemsettingsoptions-macos-windows) and [the Windows implementation](https://github.com/electron/electron/blob/v44.5.1/shell/browser/browser_win.cc). Uninstall removes the owned startup names. The actual user startup entry was enabled and read back successfully on 3 November 2026; a reboot was not performed.

Native foreground-window events detect standard Windows Snipping Tool/clipping overlays. Those overlays are exempt from fullscreen hiding. While an overlay is active, the existing notch stays centered, is raised without taking keyboard focus, and postpones automatic collapse. The normal close grace resumes afterward. Ordinary fullscreen apps retain the user's Hide while full screen behavior. Windows secure desktop and unrecognized third-party capture tools are not guaranteed to expose an equivalent signal; no claim is made that ordinary always-on-top windows can override every OS surface.

## Verification

- 83 Node tests pass, including saved intent vs actual voice readiness, startup registration/readback arguments, screenshot-overlay fullscreen exemption and the existing regression suite.
- 15 Windows save/scroll checks pass in an isolated profile, using disposable API keys and no audio uploads. They cover Save with consent off/on, saved-key decryption, native configuration payloads, draft preservation, persistent errors, real mouse-wheel input at 760 × 760 and 640 × 580 windows, bottom-control reachability, screenshot-overlay events, unchanged bounds/topmost state, and startup preference persistence.
- The rebuilt native Windows engine registers the real Ctrl+Shift+Win hook, reports `hookRunning: true`, passes its begin/finish chord self-test, and remains `recording: false`. The test then disables its temporary hook. This is not a live speech-recognition accuracy test.
- The 60-check Windows compact/timer/tool/multilingual smoke suite passes. Packaged verification and installer checksum are recorded under `artifacts/0.7.1` and `release/0.7.1`.

Reproduce with `npm test`, `npm run build:native`, `npm start -- --smoke-test --settings-save-check`, `npm start -- --smoke-test`, then `npm run dist -- --config.directories.output=release/0.7.1`.

The installer is unsigned. Quit 0.7.0 before running the 0.7.1 installer or executable. Existing saved keys and personal data are retained. For voice, save a transcription-provider key and explicitly check Allow recorded audio in Settings → Voice; Save should then report that the global hotkey is active. No real cloud audio, paid-provider accuracy, reboot/login, or actual Snipping Tool selection has been used as evidence unless separately recorded in the artifact report.
