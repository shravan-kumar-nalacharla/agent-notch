# 0.5.1 Settings visibility fix

The blank Settings window in 0.5.0 was a real regression. Controls loaded and could be changed programmatically, but an unscoped idle-island CSS selector made their ancestor `visibility:hidden`. The earlier smoke test verified DOM values and saving without checking visibility; its blank screenshot should have failed review.

A second unscoped reduced-motion transform shifted Settings left by half its width. The reproduction measured left = -373.2 DIP on this display. Both visibility and transform rules now explicitly exclude `.settings-window`, including subtle motion and the Windows reduced-motion media rule.

Changes: three selectors in `src/compact.css`; rendered visibility, centering and pointer-hit assertions in `src/smoke.cjs`; isolated six-case regression harness in `scripts/check-settings.cjs`; version 0.5.1 metadata. No data migration is needed.

Run from the source directory:

```powershell
npx electron scripts/check-settings.cjs
npm test
# Also exercises all other compact-app regressions and actual Settings visibility:
npm start -- --smoke-test
```

The focused test creates its own temporary profile without API keys. It checks standard/subtle/off app motion with both normal/reduced OS motion, including native browser hit testing of the provider dropdown, horizontal position, navigation and a saved-changes acknowledgement. Before-fix test failed with hidden/displaced controls; after-fix all six cases passed. `F:\AgentNotch-builds\logs\settings-before.log`, `settings-check\visibility.json`, `settings-after.log`, and `settings-after\visibility.json` preserve the evidence. `settings-after\settings.png` shows the rendered controls.

The release is built under `F:\AgentNotch-builds\0.5.1`; see its checksums and packaged/installed smoke logs for final artifact verification. The installer remains unsigned. Prior hardware/API/redistribution limitations in the 0.5.0 report still apply.
