# Manual terminal boundary

The Windows helper hosts one independent ConPTY session, launched only after a native user review. Shells are fixed Windows PowerShell, PowerShell 7 (when installed in its supported Program Files location) and CMD. The assistant planner has no terminal action. The working folder comes from a native directory picker, not a renderer-supplied command line. User input requires focus; only bounded terminal cursor/device/focus protocol replies can be sent without focus. Multiline pastes require review. Surviving a closed island is opt-in per session. No shell opens on app restart.

Each session owns an OS job with kill-on-close. Start/resize/close use workers, output and input use separate bounded channels, and the output drain lock is never held over synchronous ConPTY control operations. Child standard handles are explicitly null with STARTF_USESTDHANDLES so they cannot inherit the helper's JSON transport. See the [Microsoft maintainer explanation](https://github.com/microsoft/terminal/discussions/15814) and [ConPTY lifecycle documentation](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session). New native code is independently authored against the documented APIs; no Crest source is included.

Xterm.js 6 and its Fit addon are MIT-licensed runtime dependencies. The renderer loads their local files. Their DOM renderer generates style elements for measured cells and terminal colors, so the first-party page permits inline **style elements only**. Inline style attributes, inline scripts, eval, remote scripts, renderer networking, popups and navigation remain blocked. Terminal output is parsed as terminal text, never inserted as HTML. Plugin pages must have their own stricter, isolated policies and never inherit this first-party exception. This changes stylesheet policy, not script privileges.

Agent Notch retains at most 256 KiB of unread terminal text and 1,000 xterm scrollback rows, in memory. It does not log terminal content or send it to AI. PowerShell profiles are disabled and its PSReadLine history saving is disabled for the session; child programs can still write their own files. ConPTY transport is always UTF-8. Other legacy code pages are not advertised as separate transport encodings.
