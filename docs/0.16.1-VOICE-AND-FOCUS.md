# Voice assistant, typing and Focus Time — 0.16.1

Focus Time previously opened the general tool carousel. Its timer/stopwatch, breaks and duration now have a dedicated presentation without carousel arrows, dots or the All Tools menu. The timer state/backend is shared with the existing library, so active focus sessions are preserved. More Tools keeps its own grid.

The new **Voice assistant** destination has listening, processing, speaking, ready, muted and error states, a microphone-level visualization, the last spoken exchange, Start/Finish/Stop and voice settings. Home Voice, the header microphone, the assistant shortcut, wake activation and Push-to-Talk use this destination. Windows task progress and action reviews appear in the same voice interface; typed-task reviews remain in Chat. Chat's own microphone drafts a message into the composer and waits for Send. It never automatically executes the draft or inserts it into an external app. Global voice typing continues to target the user's focused app.

The microphone listening mode now governs assistant activation while global dictation retains its own enabled switch and shortcut. Windows+Ctrl+Shift dictation can run alongside Ctrl+Alt+V Push-to-Talk. Always listening can also use held-key assistant activation. Manual remains the default for new installations. Mute, Gaming/Meeting mode, call-mode and OS lock privacy gates still cover every capture path. In assistant Push-to-Talk mode, the explicit chat-dictation button is allowed as a separate typing feature; the assistant itself still requires the held key.

Name activation now has a visible on/off control and status in the Voice assistant interface. The Settings wake-name switch selects Always listening and the listening-mode selector keeps that switch consistent. Enabling name activation never unmutes the microphone. Unmuting restores the saved mode/recognizer. The screen displays the exact configured phrase; saying a different name does not activate it. Windows speech recognition must be installed; failures are shown instead of claiming the wake name is ready. Wake activation starts capture directly without waiting for a spoken greeting. Teardown explicitly cancels recognition before disposal; the acknowledgement timeout allows Windows driver teardown without falsely declaring a crash, while the native privacy gate blocks activation immediately.

## Sarvam HTTP 400

The original integration sent `reasoning_effort: "none"`, a value listed in the provider's documentation but rejected by the live service. The actual response required `low`, `medium` or `high`. Requests now use `low`. Both normal connection tests and streamed chat failures show bounded, redacted Sarvam error details. Credentials remain encrypted per provider and are never placed in diagnostics.

The user's saved key passed real connection, streamed chat, Bulbul v3 WAV synthesis and Saaras v4 transcription tests after this correction. Recognition used the generated test phrase, with no microphone audio uploaded and no audio saved. The exposed key should be replaced in the Sarvam dashboard and the replacement saved in Settings.
