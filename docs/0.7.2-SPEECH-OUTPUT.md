# Agent Notch 0.7.2 speech-output fix

The red “Voice service returned HTTP 400” message comes from Groq read-aloud, not the microphone recognizer or text-chat request. When the older Read assistant answers aloud setting was enabled, even a typed reply invoked that speech endpoint. The generic message hid the provider's explanation, so the screenshot alone cannot identify the account-side rejection.

Typed-chat read-aloud is now a separate opt-in, initially off. The existing read-aloud setting continues to control voice-chat replies. Both controls sit in Settings → Voice. An automatic speech request rechecks the master setting before starting, including queued events after read-aloud was turned off. Explicit Save & hear voice preview remains available with automatic replies off.

New/default voice configuration uses Installed Windows voice. An explicitly saved Groq choice is retained. If automatic Groq read-aloud fails, the text reply stays visible, a small speech notice explains the failure, and a matching installed Windows voice is tried. Further automatic cloud retries are paused for that session. Save & hear voice is the explicit retry route; a failed preview reports the real error instead of claiming success.

Groq HTTP errors now retain a bounded, credential-redacted error code and explanation. A `model_terms_required` response gives the model setup URL and says that the account owner or organization admin must review the model terms. The app never accepts legal terms on the user's behalf. A Groq voice setup button opens that fixed official URL. Other HTTP 400 causes are not automatically labeled as terms errors.

## Manual choices

For local playback, choose Settings → Voice → Reply voice engine → Installed Windows voice, select an available voice, and save. This avoids Groq text-to-speech requests. For silent chat, turn off Read assistant answers aloud; in 0.7.2, leave Also read typed chat replies aloud off unless desired.

To use Groq Orpheus, open the [official model playground](https://console.groq.com/playground?model=canopylabs%2Forpheus-v1-english) with the account/organization that owns the saved key. Review any model-access or terms prompt, then use Save & hear voice. The [official request documentation](https://console.groq.com/docs/text-to-speech/orpheus) confirms the model, WAV format, voices and 200-character input limit used by the app.

## Validation and limits

- 87 Node tests pass, including terms/error handling and credential redaction, master-off suppression, Windows fallback, one cloud failure followed by local-only retries, and explicit preview behavior.
- The speech-output UI smoke check exercises real typed-chat rendering with deterministic assistant replies. Typed chat stays silent by default, explicit typed read-aloud works, master-off blocks it, and the new profile defaults to system voice. It makes no cloud requests.
- Existing compact-window/settings/timer/tool regressions are run separately. Final packaged test logs and byte comparisons are under `artifacts/0.7.2`.
- No successful live Groq TTS request or real speech recognition was used as release evidence. An isolated diagnostic could not unlock the stored credential in its separate process context, so it sent no provider request. The user's exact account-side 400 remains unconfirmed; the new error details and Groq setup page provide the next diagnostic step.

Installer: `release/0.7.2/Agent Notch Setup 0.7.2.exe`, unsigned. Quit the old tray instance before installing. Saved keys, microphone settings and Windows startup configuration are retained.
