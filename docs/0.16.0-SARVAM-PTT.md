# Sarvam voice and held-key chat — 0.16.0

Ctrl+Alt+V previously appeared available in Settings even while the saved listening mode was Manual, which never installed the held-key hook. Standard voice also used the selected Windows narrator. Settings now explains the listening mode and reports whether Push-to-Talk is actually ready. A missing key or consent produces a setup message without opening the microphone. Shortcut conflicts and mute remain hard gates.

Sarvam has its own encrypted key field, independent of Groq and Gemini. In Voice Assistant, **Use Sarvam with push-to-talk** saves the Sarvam conversation/voice engines, held-key mode and spoken replies. It requires the existing cloud-audio consent and never unmutes the microphone. Hold the assigned shortcut to ask; release to finish. New installations retain Manual as the privacy default. Ordinary Sarvam voice questions use Sarvam recognition, chat and speech with one key. Desktop actions retain the shared safe executor and its selected global assistant; typed chat and dictation provider preferences are preserved.

The implementation uses Saaras v4 transcription, Sarvam 105B Conversations for answers and Bulbul v3 speech with selectable voices including Priya. Bulbul v3 is the stable short-speaker-name interface used by this UI; newer persona catalogs are not interchangeable. Canonical native 16 kHz WAV recordings exceeding the REST transcription limit are split with overlap and their transcripts joined. Language probability is not treated as speech confidence. Hindi, Telugu and English replies choose the matching speech language; additional supported language codes are validated in the adapter.

Sarvam speech errors remain visible alongside the text answer and never fall back to the Windows narrator. Mute cancels capture, transcription, generation, queued playback and synthesis requests. Voice level updates no longer clear reminder suppression during a recording. Existing reminder button ownership is retained.

## Setup

1. Create a key in the [Sarvam dashboard](https://dashboard.sarvam.ai/).
2. Save it under Settings → AI & API keys → Sarvam. Do not paste it into a chat or commit it.
3. Open Voice Assistant, allow cloud audio if desired, then choose **Use Sarvam with push-to-talk**. Check that the microphone is unmuted before holding Ctrl+Alt+V.

An API account with access and available credits is required. Gemini remains optional; this release does not diagnose the user's reported Gemini HTTP 500 or add Gemini Live held-key support.

## Verification

All 249 unit/regression tests pass, including seven new Sarvam tests for authentication, requests, streamed answers, language handling, long WAV splitting, response validation, cancellation, error redaction and voice routing. The Windows native fixture passes five held-key/microphone lifecycle checks using the actual hook and microphone, with no audio saved or uploaded. The isolated Electron Sarvam fixture passes recognition → answer → audio playback, missing-key capture blocking, release, shortcut swallowing, mute and a simulated HTTP 500 without narrator fallback. Cloud responses and utterance audio in that fixture are synthetic. The Settings check passes 23 cases, including separate encrypted keys.

Actual Sarvam API access and recognition of the user's voice still require a real key and a user trial. Synthetic Windows key events do not establish physical keyboard behavior, Discord call coexistence or Windows 10 verification. The packaged app also passes six Sarvam checks, 23 Settings checks, 13 privacy checks, six reminder pointer scenarios and eleven reminder scenarios with zero Windows toasts. The existing Gemini fixture passes eleven checks. All 132 runtime source/assets match the packaged ASAR; nine runtime payload hashes are recorded before installer construction. Installed-payload checks are recorded separately in the release evidence.
