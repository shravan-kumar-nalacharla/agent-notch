# Agent Notch 0.17.9 — automatic updates and public downloads

0.17.9 is the verified updater-enabled Windows release. The source repository stays private. Downloads and update metadata come from a separate public release-only repository:

- Public downloads: <https://github.com/shravan-kumar-nalacharla/agent-notch-releases>.
- Source: private `island-fusion` repository (not published).
- Update provider: `electron-updater` 6.8.11 with the existing NSIS target.
- Public assets: `Agent-Notch-Setup-0.17.9.exe`, `latest.yml`, the installer blockmap, `SHA256SUMS.txt`, release notes and third-party notices. No source archive, source ZIP, patch, QA archive or build evidence is published.

## Behaviour

- Checks 15 seconds after startup, every six hours while running, and from **Settings > About > Updates**.
- Downloads in the background and verifies the package against `latest.yml`.
- Asks **Restart now** or **Later**. Settings and the tray show checking, percentage, ready, up-to-date and error states.
- Prompting and installation are deferred while voice or dictation is recording, screen capture is active, a manual terminal session is open, Settings have unsaved changes, or an agent task is running. The prompt retries every 30 seconds.
- On acceptance, the app marks itself as quitting, aborts speech and uploads, stops voice and agent workers, closes the managed browser and native helper, checkpoints and closes SQLite, flushes settings, and quits.
- A temporary PowerShell helper is created through Windows Management Instrumentation so it survives the app's process job. It waits for the app PID, removes `ELECTRON_RUN_AS_NODE`, runs the verified NSIS package with `--updated /S --force-run`, and the updated app reopens.
- Settings, encrypted provider keys, notes, reminders, history, SQLite data and user documents live outside the installed folder and are preserved.
- `autoInstallOnAppQuit` stays off; a normal quit does not silently run the installer.

## Installed update proof

The complete flow was exercised on this Windows machine with two real installed builds:

1. Installed 0.17.8 silently into `F:\AgentNotch-e2e` with the NSIS installer.
2. Launched the installed app with an isolated profile and its debugging port.
3. Called `window.island.checkForUpdates()`. It reported 0.17.9 and downloaded it.
4. Called `window.island.installUpdate()`. The PowerShell/WMI helper waited for the app to exit, installed 0.17.9 silently, and the app relaunched.
5. Re-read the installed `app.asar` package version: 0.17.9. Re-read the isolated profile settings written before the update: the marker was still present. Launched the updated app: preload reported 0.17.9.

Recorded result:

```

available Version 0.17.9 is available. Downloading…
READY 0.17.9
INSTALLED VERSION 0.17.9 BASE PROFILE PRESERVED
RESTARTED 0.17.9
UPDATE E2E PASS { from: '0.17.8', to: '0.17.9' }
```

The test used `--update-test`, which redirects the app profile to a temporary directory; the real `%APPDATA%\agent-notch` profile was not used. The test installation and its registry entry are separate from `F:\AgentNotch`.

## Lyric regression decision

`tests/media-lyrics-ui.test.cjs` originally asserted an inline `style.bottom` of `22px`/`66px`. The shipped component uses explicit CSS classes and `transform` transitions, which is the newer 0.17.1 layout implementation. The test was treated as stale on mechanism, not on behaviour. It still verifies retention through lookup gaps and blank cues, hidden future lines, the previous line moving above the current line, the departing line fading out, and plain lyrics never being presented as synchronized. The opacity check accepts the last sub-percent of a 600 ms transition instead of requiring the rounded string `0`.

The uncommitted lyric layout work is therefore complete for this release, not an unchanged baseline.

## Release pipeline

`.github/workflows/release.yml` runs only for pushes to the `release` branch or an explicit manual dispatch. It runs the full test suite, restores .NET 8 and the matching Playwright Chromium, checks the package version, requires a signing certificate unless the initial bootstrap is explicitly allowed unsigned, builds NSIS with `--publish never`, verifies the installer hash against `latest.yml` and `app-update.yml`, runs the packaged smoke test, then publishes the exact tested assets with the `RELEASE_TOKEN` secret to the public repository. A version tag is never overwritten.

## Signing and rollout limits

This build is unsigned because no Windows code-signing certificate is installed on this machine. SmartScreen can warn. The workflow fails closed for unsigned releases except for a manual initial bootstrap. A signed release should replace this build through the normal update channel; users do not need to reinstall.

## Rollback

Publish a higher version containing the corrected or restored code. Never delete a release and expect installed machines to downgrade. `allowDowngrade` remains false.
