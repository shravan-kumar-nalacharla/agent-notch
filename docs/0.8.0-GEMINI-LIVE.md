# Gemini Live conversation — 0.8.0

## Set up

1. Quit the older Agent Notch tray instance and run `release/0.8.0/Agent Notch Setup 0.8.0.exe`.
2. Open Settings → Voice typing → Voice conversation → **Get a Gemini API key**. Create your own key in [Google AI Studio](https://aistudio.google.com/apikey). Existing Groq keys cannot authenticate to Google.
3. Click **Enter Gemini key**. This selects Gemini under Providers and focuses the key field. Paste the key in the app and save. Your assistant and global-dictation providers can remain unchanged.
4. Return to Voice typing, choose **Gemini Live**, enable **Allow recorded audio…** and **Read assistant answers aloud**, then save. Typed answers remain silent unless their separate opt-in is enabled.
5. Use **Save & check Gemini Live** to check key/model access without opening the microphone. If Google rejects access, check the API key's project, API restrictions, model availability, billing and quota in AI Studio; use the specific error shown by the check.
6. Use headphones, then click the notch microphone and speak. Conversation continues across turns and supports interruption. Click the microphone again or press Escape to end it. A disconnected/expired session requires a new microphone click.

## Behavior

The Electron main process connects to Google's documented [Gemini 3.8 Live model](https://aistudio.google.com/docs/models/gemini-3.8-live) through the [Live WebSocket API](https://aistudio.google.com/api-reference/live). The existing WASAPI capture supplies 16 kHz mono PCM; one Web Audio clock queues 24 kHz response PCM. No additional runtime dependency or second conversation microphone capture is introduced. Keys stay encrypted in Windows storage and never enter renderer state or playback events.

Cloud audio consent is required before connecting. Read-aloud off suppresses playback; Google still generates audio as part of the Live session, so this does not eliminate API usage. Follow-input and explicit spoken-language settings apply to the conversation. Input/output transcripts appear in chat and local voice history; raw microphone audio is not saved. Standard voice chat, selected-text editing, meeting transcription and global dictation retain their existing provider paths. Live conversation itself has no desktop execution tools.

Stopping, Escape, failed setup, connection loss, microphone-engine exit and upload backpressure close the cloud session. A global dictation started during pending setup cancels setup without cancelling that dictation. Meetings and live conversation cannot start competing microphone sessions.

## Verification and limits

97 Node tests cover handshake framing, error redaction, consent, master mute, streamed transcripts/audio, multiple turns, interruption, cancellation during setup, native-helper exit, safe dictation separation, queue timing and playback cancellation, plus existing regressions. Windows smoke checks cover the Settings save/scroll path, Gemini settings and live-chat UI, silent typed replies, master mute, compact geometry and existing desktop tools. Tests use temporary profiles and deterministic cloud/audio fixtures; they do not capture the user's microphone or contact Google.

A live Google conversation, account-specific quota/billing, physical microphone quality, speaker echo and Hindi/Telugu/code-switching accuracy remain unverified because no Gemini key is saved on this computer. Use headphones: this WASAPI path does not add acoustic echo cancellation. The installer is unsigned.
